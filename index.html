Лабораторная работа №2. Простой сайт на Django

Студент: Фёдорова Мария
Группа: K3339
Вариант: 4 — Список туров туристической фирмы

Цель работы

Овладеть практическими навыками реализации web-сервисов средствами Django: модели данных, CRUD-интерфейсы, разграничение прав, PostgreSQL, оформление отчёта в MkDocs.

Индивидуальный вариант

Хранится информация о названии тура, турагентстве, описании тура, периоде проведения, условиях оплаты и стране направления.

Реализованный функционал:

  1. Регистрация новых пользователей.
  2. Просмотр и резервирование туров; пользователь может редактировать даты и удалять свои бронирования.
  3. Отзывы к турам: даты тура, текст, рейтинг (1–10), автор.
  4. Администратор подтверждает резервирование в Django-admin и в клиентской панели (is_staff).
  5. В клиентской части (для администратора) формируется таблица всех проданных туров по странам.

Дополнительно для максимального балла:

  • стилизация интерфейса;
  • пагинация списка туров;
  • поиск, фильтрация по стране/агентству и сортировка;
  • разграничение прав в клиентском интерфейсе по is_staff.

Архитектура

Клиент-серверное приложение:

Backend Django 6 + Django REST Framework, Token Authentication
БД PostgreSQL (tours_db)
Frontend React (Vite) + axios + SCSS
Admin Django-admin + отдельная React-страница для staff

Модель данных

Country

Страна направления тура.

  • name — уникальное название страны

Agency

Турагентство.

  • name — название агентства

Tour

Тур.

  • name — название
  • agency — FK → Agency
  • country — FK → Country
  • description — описание
  • start_date, end_date — период проведения
  • payment_terms — условия оплаты
  • price — стоимость

Reservation

Бронирование тура пользователем.

  • user — FK → User
  • tour — FK → Tour
  • start_date, end_date — выбранные даты поездки
  • created_at — дата создания заявки
  • is_confirmed — подтверждение администратором (по умолчанию False)

При изменении дат пользователем флаг is_confirmed сбрасывается — требуется повторное подтверждение.

Review

Отзыв о туре.

  • user — автор
  • tour — тур
  • text — текст комментария
  • rating — рейтинг 1–10
  • start_date, end_date — даты тура (подставляются из тура при создании)
  • created_at — время публикации

API-интерфейсы

Базовый префикс: /api/

Метод URL Доступ Назначение
POST /register/ все регистрация
POST /login/ все получение токена
GET /me/ auth текущий пользователь (is_staff)
GET /tours/ все список туров (поиск, фильтры, пагинация)
GET /tours/<id>/ все карточка тура
GET/POST /reservations/ auth свои бронирования / создать
GET/PATCH/DELETE /reservations/<id>/ auth просмотр, правка дат, удаление
GET/POST /reviews/ GET все / POST auth отзывы
DELETE /reviews/<id>/ auth (свой) удаление отзыва
GET /admin/reservations/ staff все бронирования
PATCH /admin/reservations/<id>/confirm/ staff подтвердить
GET /admin/stats/sold-by-country/ staff проданные туры по странам

Параметры списка туров:

  • search — поиск по названию, описанию, стране, агентству
  • country, agency — фильтрация
  • ordering — start_date, price, -price, name
  • page — номер страницы (размер страницы: 4)

Клиентские интерфейсы

Главная — список туров (/)

Каталог туров с карточками: страна, название, описание, агентство, даты, цена.

Фильтры и поиск, сортировка, пагинация «‹ / ›».

Карточка тура (/tours/:id)

Полное описание, условия оплаты, блок бронирования (для авторизованных), список отзывов и форма нового отзыва с рейтингом.

Регистрация / вход (/register, /login)

Создание аккаунта и получение токена. После входа загружается профиль с флагом is_staff.

Мои бронирования (/reservations)

Список заявок текущего пользователя. Можно изменить даты (модальное окно) или удалить бронь. После правки дат статус снова «ожидает подтверждения».

Панель администратора (/admin)

Доступна только при user.is_staff. Ссылка в навбаре скрыта для обычных пользователей.

Возможности:

  • список всех бронирований с кнопкой «Подтвердить»;
  • таблица проданных (подтверждённых) туров: страна, тур, клиент, даты.

Django-admin (/django-admin/ или стандартный /admin/ backend)

Администратор может подтвердить резервирование галочкой is_confirmed в списке бронирований (list_editable).

Разграничение прав

Действие Гость Пользователь Staff
Просмотр туров и отзывов ✓ ✓ ✓
Бронирование / свои заявки ✓ ✓
Отзывы ✓ ✓
Панель /admin и таблица продаж ✓
Подтверждение в Django-admin ✓

На клиенте проверка user.is_staff управляет пунктом меню и доступом к /admin (редирект на главную). На API — IsAdminUser / IsAuthenticated.
